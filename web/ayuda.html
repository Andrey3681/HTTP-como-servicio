Ayuda / Verificación operativa

Guía alineada a los specs (Nota parcial 3, diseño/arquitectura/OpenAPI) para aprovisionar, validar y diagnosticar instancias HTTPaaS.

Reglas de aprovisionamiento

  • hostname (subdominio): patrón ^[a-z0-9][a-z0-9-]{1,30}[a-z0-9]$, 3–32 caracteres, minúsculas/números/guiones, sin iniciar/terminar con guion. Debe ser único en el dominio.
  • Reservados: ns, router, gateway, localhost.
  • Contenido web: archivo .zip (requerido) con el sitio/app; se despliega en el DocumentRoot de la instancia (p. ej. /var/www/vhosts/<host>/).
  • Resultado: VM (disco multiconexión/VirtualBox), VHost Apache, registro DNS en la zona cloud.local y FQDN <host>.cloud.local.

Checklist de verificación

# Salud del orquestador
curl -s http://localhost:8080/api/salud | jq .

# Resolución DNS (Bind9, zona cloud.local)
dig @192.168.10.10 <host>.cloud.local +short
dig @192.168.10.10 cloud.local SOA +noall +answer

# Acceso HTTP a la instancia
curl -I http://<ip>/
curl http://<host>.cloud.local/

# Disco base multiconexión (VirtualBox)
VBoxManage showmediuminfo "ApacheServer.vdi"  # Type: multiattach

Errores comunes

  • 400 — nombre inválido o duplicado, o .zip faltante/inválido. Verifica el patrón de hostname y el archivo.
  • 404 — instancia no encontrada (al consultar/eliminar). Refresca el listado.
  • 500 — fallo en VM/DNS/despliegue; el orquestador aplica rollback (compensación) para evitar estado inconsistente.
  • Backend inaccesible — revisa que el servidor Go esté activo (task run) y consulta Salud.
